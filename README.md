# BarberRome — artist site

Static, mobile-first artist site for **BarberRome** (BarberROME on DSPs): Bay Area rapper from San Francisco, living in Vallejo, working barber.
Plain HTML/CSS/JS generated by a zero-dependency Node script. Netlify-ready (forms, headers, optional functions). No framework, no trackers, no WebGL.

## Quick start

```bash
npm run build                 # → dist/   (Node 18+, no npm install needed)
npm run preview               # build + serve dist/ on http://localhost:8080
npm test                      # build + ~840 static checks (npm run test:pages for the GitHub Pages build) (SEO, H1, links, alt, forms, JSON-LD, secrets, JS syntax)
node scripts/e2e.mjs          # interaction checks in headless Chrome (needs preview running; CHROME=/path/to/chrome)
npm run build:draft           # → dist-draft/ with orange "DRAFT" notes where content is missing
npm run images                # re-crop/compress images from source-media/ (Python 3 + Pillow + numpy)
```

Set the real domain before launch: `SITE_URL=https://your-domain.com npm run build` (or `siteUrl` in `src/data/site.json`, or `SITE_URL` env in Netlify). On Netlify with Git/CLI deploys, the build falls back to Netlify's own `URL`. **The prebuilt `dist/` in the zip uses `http://localhost:8080` for canonical/OG/sitemap — rebuild with SITE_URL before a drag-and-drop deploy.**

- Local preview of the Pages build: `npm run build:pages && PORT=8081 node scripts/preview.mjs` → http://localhost:8081/ ; tests: `npm run test:pages`, and `BASE=http://localhost:8081 FORMS_MODE=formsubmit node scripts/e2e.mjs`.

## Email forwarding (FormSubmit) — enabled on Pages, waiting for activation

Goal: signup + booking submissions emailed to **iv.forthepeople@gmail.com** from the GitHub Pages site, no server and no account. FormSubmit (https://formsubmit.co, docs https://formsubmit.co/documentation) does this with a plain HTML form `action`. The live Pages build uses it (`FORMS_MODE: formsubmit` in the workflow, endpoint `https://formsubmit.co/iv.forthepeople@gmail.com` in `site.json`). Nothing is forwarded until the inbox owner clicks FormSubmit's activation email; until then `forms.formsubmitActive` is `false` and each form says email delivery is still being switched on. After activation, set it to `true` and push.

What the `formsubmit` mode does (`FORMS_MODE=formsubmit` + `forms.formsubmitEndpoint`):
- Forms POST natively to the endpoint (no AJAX, so FormSubmit's reCAPTCHA spam check stays on), with `_subject`, `_template=table`, a `_honey` honeypot, and `_next` = this site's `/join/thanks/` or `/booking/thanks/` (full URL, as FormSubmit requires). JS only validates (email-or-phone, consent) before letting the browser submit.
- Each form says "Sent by email through FormSubmit (formsubmit.co)", and `/privacy/` gets a third-party note.
- Thank-you pages are built again; the join one still says the unreleased drop isn't posted yet unless `reward.url` is set.

Activation (needs the owner, one time):
1. Done: endpoint set and the workflow builds with `FORMS_MODE: formsubmit`.
2. Submit either form once on the live site. FormSubmit then emails **iv.forthepeople@gmail.com** an activation link; click it (check spam). Until that click nothing is forwarded (FormSubmit holds submissions up to 30 days and delivers them after confirming).
3. Optional: the activation email includes a random-string alias. Swap it into `formsubmitEndpoint` so the raw address isn't in the HTML (it's already public via the mailto buttons, so this is just spam hygiene).
4. Send one real test from the live site and check it arrives.

Limits: free tier, third-party processing, reCAPTCHA page between submit and thank-you, no list management (it's email notifications, not a mailing list). For a real list later, point the forms at a list tool (Laylo, Mailchimp, etc.) or use Netlify + the functions relay.

Tests never submit in this mode (`scripts/e2e.mjs` only checks wiring), because any POST to FormSubmit sends real mail.
To check the build locally: `SITE_URL=https://barberrome.com FORMS_MODE=formsubmit FORMSUBMIT_ENDPOINT=https://formsubmit.co/iv.forthepeople@gmail.com npm test`.

## Deploy (Netlify — for working forms)

1. Push this folder to a Git repo, or `netlify deploy` with the CLI. Build command and publish dir come from `netlify.toml`.
2. Set `SITE_URL` in Site settings → Environment variables (your custom domain).
3. Forms: Netlify auto-detects the `join` and `booking` forms on deploy. Turn on form notifications (email/Slack/webhook) in the Netlify UI. Submissions are in Netlify → Forms.
4. Optional relay mode: set `"forms": {"mode": "function"}` in `site.json`, and set `SUBSCRIBE_WEBHOOK_URL` / `BOOKING_WEBHOOK_URL` env vars (Zapier/Make, Laylo, a Mailchimp proxy, Google Apps Script…). `netlify/functions/subscribe.mjs` and `booking.mjs` validate, drop honeypot hits, and forward JSON. With no webhook set they return 503, so the page shows "Not sent" — never a fake success.

Other static hosts work for the pages; forms then need `mode: "function"` on a host with functions, or your own endpoint.

## How it behaves

| Piece | Behavior | Without JS |
|---|---|---|
| Hero | Graded still of the black 5.0 convertible from BarberROME's “California livin’” video (wide) / SF-cap still from the ALL I KNOW video (mobile), slow horizontal drift, letterbox bar, BARBER / ROME wordmark (the only H1). Optional muted loop via `hero.loopVideo`. | Still image |
| Lead player | Ready on load, nothing plays until tapped. Tap loads the privacy-enhanced YouTube embed with sound. Waveform pulses + hero contrast lifts only while YouTube reports "playing" (postMessage, no API script). Lead track = `leadTrack` in site.json. | Play links to the track page |
| Stream | Bottom-sheet chooser (Spotify / Apple Music / Tidal / YouTube / YouTube Music), focus trapped, Esc closes. Each row says where it goes: the track title, or "Artist page" for Spotify/Tidal until track URLs are added. | Jumps to footer links |
| Join the list | Hero button opens an inline form; full form again right after the track grid; compact form on each track page. Email **or** phone, explicit consent checkbox (email + SMS language), honeypot. | Native POST to Netlify → `/join/thanks/` (email required) |
| Track grid | 5 tiles. Hover shows the credit line (or a hook line if one is ever added to `tracks.json`); tap ▶ expands the tile in place with the video + links; opening another closes and unloads the first; Esc closes. Title → track page. | Tiles link to track pages |
| Track pages | `/tracks/<slug>/`: video facade (loads on tap), release date + credits, 5 streaming buttons (Apple + YouTube go to the track; Spotify + Tidal go to the artist page and are labeled "artist page"), extra videos, join form, prev/next. No lyrics section for now. | Poster + "Watch on YouTube" |
| Chair to Mic | 5 swipeable first-person cards, scroll-snap, prev/next buttons, keyboard-scrollable. | Native horizontal scroll |
| Footer | SF → Vallejo with two location stills, listen + follow links, booking inquiry form. | Native POST → `/booking/thanks/` |
| Reduced motion | All drift/pulse/transitions off. | — |

Events (`stream_click`, `stream_open`, `play_click`, `tile_expand`, `track_page_open`, `join_cta`, `join_open`, `join_submit`, `booking_submit`, `social_click`) go to `window.dataLayer` and a `br:track` DOM event; add `?debug` to the URL to log them. Paste a provider snippet into `src/partials/analytics.html` if you want one.

SEO: exact title/description from the brief on `/`, per-track titles/descriptions, canonical on every page, OG + Twitter cards (1200×630 still), JSON-LD `MusicGroup` + `Person` (genre, Vallejo + San Francisco, sameAs Instagram/Spotify/Apple Music/Tidal/YouTube/YouTube Music, 5 `MusicRecording`s), per-track `MusicRecording` + `VideoObject` + breadcrumbs, `sitemap.xml`, `robots.txt`, noindex on thank-you/404 pages. Images are WebP + JPEG fallback with `srcset`, lazy below the fold, self-hosted fonts (Barlow Condensed, OFL), ~15 KB JS, ~20 KB CSS.
